# CAPTCHA flow map (pre-autocaptcha.pro)

AUTO = /Users/MAC/Desktop/DEV/nz-working-holiday-automation
WEB = /Users/MAC/Desktop/DEV/nz-working-holiday

Key fact: there is NO automatic fallback/ordering between providers. The user picks exactly one `captchaMode` per run (`manual | capsolver | 2captcha`). A provider failure falls back to MANUAL solving in Chrome, never to the other provider. "Fallback" for a third provider = add a third mode, not an ordering chain.

### Solver interface a new provider must match
Both solvers export `solveRecaptchaV2(challenge: {websiteURL: string; websiteKey: string}, apiKey: string, signal: AbortSignal[, log?: (m: string) => void]): Promise<string>` returning the g-recaptcha token. Conventions:
- AUTO/workflow/capsolver.ts: error class `CapSolverError(category: "timeout"|"service"|"response"|"session")` with message `CapSolver ${category}` (never includes bodies/URLs/keys). POST JSON to https://api.capsolver.com/{createTask,getTaskResult} with `{clientKey, ...}`; task `ReCaptchaV2TaskProxyLess`; `redirect:"error"`, per-request `AbortSignal.timeout(15000)` combined with caller signal and a 120s overall deadline; no createTask retry; poll every 3s, up to 40; `signal.aborted` => rethrow `signal.reason`; deadline/TimeoutError => category timeout; `recaptcha-ca-e/-t` in solution => "session"; zod `responseSchema`.
- AUTO/workflow/two-captcha.ts: `TwoCaptchaError(category, providerCode?)` with extra categories balance/auth/ip/unsolvable/busy/proxy, `transient` flag, `categoryFor(errorId)`, `safeProviderCode` (/^ERROR_[A-Z0-9_]{1,60}$/), `formatDuration` (also imported by run.ts), `TWO_CAPTCHA_BUDGET_MS=180000`, 5s polling, retries only getTaskResult on transient failures (max 2), optional `log` trace callback, extra `getTwoCaptchaBalance`. https://api.2captcha.com, task `RecaptchaV2TaskProxyless`, taskId numeric.
- Never log the key; run.ts logs only key length; cloud.ts registers it with `registerLogSecret`.
